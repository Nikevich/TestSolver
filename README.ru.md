# TestSolver

Локальное приложение для проверки тестовых материалов на глубину знаний, на которых они основаны: проходит тест целиком через локальную языковую модель и показывает, какие вопросы проверяют понимание предмета, а какие закрываются общими знаниями модели.

Пользователю нужен только сам `TestSolver.exe` и установленный **Ollama** или **opencode**. Node.js, Python и дополнительные библиотеки не требуются — Chromium и Node уже внутри приложения.

## Зачем этот проект

В последнее время технологии ИИ всё активнее входят в повседневную жизнь, особенно у молодёжи. Из-за этого у учебных заведений растёт потребность составлять тесты так, чтобы их нельзя было пройти одной нейросетью.

При этом качественный тест нельзя собрать по первым ссылкам из интернета. Материал должен опираться на тщательный анализ предмета, лекционные материалы и реальный преподавательский опыт. Если вопрос требует знания конкретной лекции, а не общих сведений, модели, обученной на открытых данных, ответить на него практически невозможно — нужного материала в её обучении просто нет.

Проверить, так ли это, вручную дорого: нужно пройти десятки вопросов и отдельно отследить, где модель действительно знает ответ, а где угадала по формулировке. TestSolver автоматизирует этот прогон: открывает тест, читает вопросы, отвечает локальной моделью, фиксирует уверенность и обоснование. По журналу видно, какие вопросы «прозрачны» для ИИ и требуют переработки.

Проще говоря, это измерительный инструмент для автора теста, а не способ сдать чужой экзамен.

### Пример использования

1. Автор загружает свой тест (или его тестовую копию) во встроенный браузер.
2. Запускает полный прогон с локальной моделью.
3. Получает таблицу: вопрос → выбранный ответ → уверенность → короткое обоснование.
4. Смотрит, где модель уверенно отвечает без лекционного материала, и переписывает такие вопросы: добавляет привязку к конкретной лекции, требует рассуждения, убирает подсказки в формулировке.
5. Повторяет прогон и сравнивает результаты.

## Что показывает прогон

| Метрика | Что означает |
|---|---|
| Доля пройденных вопросов | Сколько вопросов модель закрыла без ошибок разбора страницы |
| Уверенность (`confidence`) | Насколько модель сама считает ответ надёжным; низкая уверенность — сигнал, что вопрос требует знания, а не догадки |
| Обоснование (`reason`) | Краткое объяснение модели: видно, отвечает она по существу или по совпадению слов |
| Ошибки разбора | Вопросы, которые не удалось прочитать из DOM (кандидаты на vision-фолбэк и на проверку вёрстки) |
| Экспорт | Таблица ответов в JSON/CSV — основа для методического разбора |

Результат прогона — не оценка студента, а карта качества теста: какие вопросы проверяют глубину, а какие теряют смысл перед лицом нейросети.

## Быстрый старт

1. Запустить `TestSolver.exe` (или `npm start` в режиме разработки).
2. Вставить адрес теста в строку сверху → **Перейти**. Логин/пароль вводятся в этом же окне, сессия сохраняется между запусками.
3. Проверить бэкенд в панели справа:
   - **Ollama** — должен быть запущен сервер и скачана модель:
     ```
     ollama pull qwen2.5:7b-instruct
     ollama pull qwen2.5vl:7b        # для vision-фолбэка
     ```
   - **opencode** — должен быть в PATH (`opencode --version`). Модель выбирается из списка `opencode models`.
4. Нажать **Старт** (или `Ctrl+Shift+S`).

Прогон останавливается сам, когда на странице больше нет вариантов ответа, когда достигнут лимит вопросов или когда нажата кнопка **Стоп**.

## Что умеет

| Возможность | Детали |
|---|---|
| Встроенный браузер | `WebContentsView`, отдельный профиль `persist:testsolver` — логин сохраняется |
| Два бэкенда | Ollama (`/api/chat`, structured JSON) и `opencode run --format json`; переключение в UI |
| Полный прогон | выбор варианта → пауза → «Продолжить» → ожидание нового вопроса |
| Текстовые ответы | вопросы с полем ввода: число, слово, последовательность номеров (например `15432`) |
| Устойчивость к перезагрузкам | состояние прогона в main-процессе, а не в странице |
| Vision-фолбэк | скриншот → `qwen2.5vl` извлекает вопрос и варианты → ответ сопоставляется с DOM |
| Журнал | `answers.jsonl` + `app.log`, таблица ответов и экспорт JSON/CSV |
| Настройки с дефолтами | форма на вкладке «Настройки», сброс поля/всего, `config.json` |

Ограничения: drag-and-drop не поддерживается; для checkbox-вопросов модель может вернуть несколько индексов.

Если в вопросе есть нумерованный список («1. …», «2. …») и поле ввода, ответ должен быть перестановкой номеров `1..N` без разделителей — при неверном формате модель переспрашивается один раз.

## Настройки

Файл: `%APPDATA%\TestSolver\config.json` (в portable-режиме — рядом с exe). При первом запуске создаётся автоматически. Любой отсутствующий ключ = значение по умолчанию.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `backend` | `ollama` | Кто отвечает на вопросы: локальная Ollama, CLI opencode или `mock` без модели (для отладки). |
| `ollama.url` | `http://127.0.0.1:11434` | Адрес локального сервера Ollama. |
| `ollama.model` | `qwen2.5:7b-instruct` | Имя модели из `ollama list`. |
| `ollama.visionModel` | `qwen2.5vl:7b` | Модель для распознавания скриншота (vision-фолбэк). |
| `ollama.temperature` | `0` | Температура генерации (0–2); `0` — максимально детерминированно. |
| `ollama.numCtx` | `4096` | Размер контекстного окна модели. |
| `ollama.keepAlive` | `30m` | Сколько держать модель в памяти после запроса. |
| `ollama.timeoutMs` | `120000` | Таймаут ожидания ответа модели, мс. |
| `opencode.bin` | `opencode` | Имя в PATH или полный путь к `opencode.exe`. |
| `opencode.model` | `""` (по умолчанию из opencode) | Модель в формате `provider/model`; пусто — модель opencode по умолчанию. |
| `opencode.timeoutMs` | `180000` | Таймаут ожидания ответа CLI, мс. |
| `automation.mode` | `auto` | `auto` — всё автоматически; `confirm` — подсветить ответ и ждать ручного нажатия «Продолжить». |
| `automation.delayMs` | `3000` | Пауза после выбора ответа перед «Продолжить», мс. |
| `automation.jitterPct` | `30` | Случайный разброс задержки, %. |
| `automation.maxQuestions` | `0` (без лимита) | Сколько вопросов пройти за прогон; `0` — до конца теста. |
| `automation.clickNext` | `true` | Нажимать «Продолжить» автоматически. |
| `automation.dryRun` | `false` | Только подсвечивать и логировать ответы, не кликая по странице. |
| `automation.questionChangeTimeoutMs` | `15000` | Сколько ждать появления нового вопроса после клика, мс. |
| `automation.postClickWaitMs` | `1200` | Дополнительная пауза после загрузки страницы, мс. |
| `automation.maxParseFailures` | `3` | Сколько ошибок разбора подряд допустить до остановки. |
| `automation.stopOnLowConfidence` | `false` | Останавливаться, если уверенность модели ниже порога. |
| `automation.minConfidence` | `0.4` | Порог уверенности для предыдущей опции (0–1). |
| `automation.startUrl` | `""` | Стартовая страница теста, открывается в браузере приложения. |
| `vision.enabled` | `true` | Включать vision-фолбэк, когда текст вопроса не удалось прочитать. |
| `vision.maxPerRun` | `10` | Максимум vision-вызовов за прогон; `0` — без лимита. |
| `vision.saveScreenshots` | `false` | Сохранять скриншоты в папку логов (могут содержать персональные данные). |
| `logging.dir` | `%APPDATA%\TestSolver\logs` | Папка логов; пусто — папка данных приложения (в portable-режиме рядом с exe). |
| `logging.answersJsonl` | `true` | Писать `answers.jsonl` — по строке на каждый вопрос. |
| `logging.rotateMb` | `10` | Размер `app.log` до ротации, МБ. |
| `logging.level` | `info` | Подробность журнала: `debug`, `info`, `warn`, `error`. |
| `ui.language` | `en` | Язык интерфейса: `en` или `ru`; статусы прогона и промпты к модели тоже следуют ему. |
| `ui.panelWidth` | `400` | Ширина боковой панели, px; меняется перетаскиванием. |
| `ui.theme` | `system` | Тема оформления: как в системе, тёмная или светлая. |

CLI-флаги (не сохраняются, действуют на запуск):

```
TestSolver.exe --backend opencode --model anthropic/claude-sonnet-4
TestSolver.exe --set automation.delayMs=2500 --set automation.dryRun=true
TestSolver.exe --reset ollama.temperature
TestSolver.exe --portable        # config.json рядом с exe
TestSolver.exe --headless        # окно не показывается (для проверки запуска)
```

## Сборка exe

```powershell
npm install
npm run dist                    # NSIS-инсталлятор + portable
npm run dist:portable           # только portable
```

Результат в `dist\`:

| Файл | Что это |
|---|---|
| `TestSolver-1.0.0-x64.exe` | NSIS-инсталлятор (рекомендуется): установка в `%LOCALAPPDATA%`, ярлыки |
| `TestSolver-1.0.0-portable.exe` | один файл без установки, распаковывается в `%TEMP%` при запуске |

`npm` и Electron нужны только на машине сборки. Пользователь получает готовый exe.

Если `npm install` не скачал бинарник Electron (политика `allowScripts`):

```powershell
node node_modules\electron\install.js
```

Неподписанный exe вызовет предупреждение SmartScreen («Подробнее → Выполнить всё равно»). Для личного инструмента это нормально; для распространения нужен код-сертификат.

## Разработка и проверка

```powershell
npm start        # приложение с DevTools-логами в консоли
npm run smoke    # headless-тесты: парсер, клики, конфиг, полный цикл на mock
npm run test:adapters  # адаптеры Ollama (фейковый сервер) и реальный opencode CLI
```

Smoke-тест использует `fixtures/test-page.html` — локальную копию страницы теста с пятью вопросами, перезагрузками страницы и страницей результатов. Он не обращается к реальному сайту и не требует модели (`backend: mock`).

Структура:

```
src/
  main/          main.js, automation.js, dom.js, config.js, logger.js, prompts.js, solver.js
  main/llm/      ollama.js, opencode.js
  preload/       preload.js (contextBridge)
  renderer/      index.html, app.js, styles.css
  shared/        schema.js (настройки и дефолты), ipc.js
fixtures/        test-page.html
assets/          icon.ico, icon.png (генерируются `npm run icon`)
scripts/         smoke.js, test-adapters.js, make-icon.js, screenshot.js
```

`npm run screenshot` собирает PNG панели интерфейса (`ui-control.png`, `ui-settings.png` в `%TEMP%`) без запуска модели — удобно проверять вёрстку. `npm run icon` перегенерирует `assets/icon.ico` (синий скруглённый квадрат с галочкой), который попадает в exe и в ярлыки.

## Диагностика

| Симптом | Что делать |
|---|---|
| `Ollama: нет связи` | Запустить Ollama (`ollama serve` или приложение из трея), проверить `http://127.0.0.1:11434/api/tags` |
| `Модель «...» не найдена` | `ollama pull <модель>` или выбрать другую на вкладке «Управление» |
| `opencode не найден в PATH` | Указать полный путь к `opencode.exe` в настройке `opencode.bin` |
| Кнопка «Старт» не находит вопрос | Убедиться, что страница теста загрузилась и есть варианты (`input[type=radio]`/`checkbox`) или поле ввода; нажать «HTML страницы» на вкладке «Лог» и посмотреть сохранённый файл в папке логов |
| Ответ выбирается, но вопрос не меняется | Увеличить `automation.questionChangeTimeoutMs`; проверить, что кнопка называется «Продолжить/Далее/Следующий» |
| Вопрос с полем ввода не заполняется | Нажать «HTML страницы» и проверить, что поле не поиск/логин; поле должно быть видимым `input`/`textarea` |
| Модель отвечает медленно | Взять модель поменьше (7B) или уменьшить `ollama.numCtx` |
| Нужно проверить без кликов | Включить `automation.dryRun` — ответы только подсвечиваются |

При ошибке разбора страница автоматически сохраняется в папку логов как `no-question-<timestamp>.html`; кнопка «HTML страницы» делает то же самое по запросу.

Приватность: журналы и скриншоты (если включены) остаются локально; наружу уходят только запросы к локальной модели. При использовании `opencode` с облачной моделью текст вопросов уходит провайдеру модели.

## Назначение и границы применимости

Проект предназначен для проверки тестовых материалов на глубину знаний, на которых они основаны: он помогает автору увидеть, какие вопросы опираются на реальный лекционный материал, а какие можно закрыть общими знаниями модели.

Проект не предназначен для сдачи чужих экзаменов, аттестаций и любых испытаний с контролем доступа или прокторингом. Использовать его следует только на материалах, права на которые принадлежат пользователю, и в пределах правил своей организации.

Решение о допустимости автоматизированного прогона теста принимает владелец теста и учебное заведение. Ответственность за соблюдение правил учреждения, условий использования площадки тестирования и законодательства своей страны лежит на пользователе.
